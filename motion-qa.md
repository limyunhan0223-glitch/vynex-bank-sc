# Motion and performance QA

Scope: motion/performance only; approved scene models, materials, UI, lighting and endpoint poses retained.

Causes found: the camera compensated for an expanded canvas before resize had occurred; Html and phone/camera projections updated independently; environment children were recreated on React renders, retriggering the one-frame reflection capture; oversized inherited CSS-variable invalidation, overlapping backdrop filters and on-click screen/raster preparation added stalls. The old 2.8-second tween plus damping also produced an extended settling tail.

Changes: ordered render callbacks (camera -2, phone -1, Html 0), a fixed Html anchor with a single projected screen matrix, viewport compensation based on actual dimensions, early canvas/screen preparation during offscreen entrance, memoized unchanged lighting/environment, target/current focus damping, rotation leading translation slightly, 1.45-second overlapping target animation, independent lock/login opacity/depth resolves, restrained separately damped phone parallax. GSAP now targets shade data and the render loop alone writes shade opacity. The existing single ScrollTrigger and 1.3 scrub remain. No additional ScrollTriggers.

Rendering: same single canvas, 38 draw calls and about 19,236 triangles in the phone scenes; existing low-resolution defocused Scene 03 buffer is prepared earlier, keeping its pixel budget close to the previous smaller viewport. Phone HTML stays high resolution. Fixed blurred-background crossfade replaces continuously filtering the whole viewport. Temporary overlapping backdrop work is disabled during movement and restored at rest. Static screen dimensions are no longer written every frame. UI is mounted before click to prepare resources, inert until settled, and cleared when inactive. React state updates are threshold events only.

Browser checks: 1920x1080 desktop and 390x844 mobile; small incremental scrolls, large gestures, quick reversals, notification click, reverse transition, pointer movement and demo submission. No console errors. One canvas. Form values cleared immediately on submission. Tests cover damping equivalence at 60/90/120 Hz, invariant projection across resize, overlapping UI endpoints and existing form safety. All 14 tests pass; typecheck and production build pass, with the existing large-chunk warning.

Observed pacing: transition settles in about 1.46-1.48 seconds; settled rendering roughly 58-60 fps. Early observed 135-193ms spikes were reduced to approximately 44-48ms in later desktop samples; most later frames were 16-20ms. Some frames still exceed the 16.7ms budget. These are local in-app browser measurements, not a guarantee of perfect 60fps on every device. Wheel-like and small trackpad-like increments were exercised through browser automation; physical hardware and 90/120Hz panels were not tested. Reduced-motion branches were inspected rather than OS-emulated.
